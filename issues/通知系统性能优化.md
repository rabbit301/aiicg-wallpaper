# 通知系统性能优化任务

## 背景
当前通知系统存在性能问题：
- `InitUserNotifications`函数使用低效的N+1查询模式
- 用户需要手动调用API初始化通知
- 每次都要遍历所有通知，效率低下

## 优化目标
1. 将N+1查询优化为单一高效SQL操作
2. 用户注册时自动初始化通知
3. 移除不必要的临时API接口
4. 为现有用户提供平滑迁移

- [x] 分析现有问题
- [x] 优化InitUserNotifications函数

## 实施详情

### 1. 优化InitUserNotifications函数
- 替换低效的N+1查询为单一高效SQL语句
- 使用PostgreSQL的INSERT ... SELECT ... WHERE NOT EXISTS语法
- 性能提升预计10倍以上

### 2. 修改用户注册流程
- 在UserService中添加NotificationService依赖
- 用户注册成功后自动调用通知初始化
- 添加错误处理，确保初始化失败不影响注册

### 3. 移除临时API接口
- 注释掉 `/notifications/init` 路由
- 添加说明注释表明已废弃原因

### 4. 创建迁移脚本
- 为现有用户批量创建通知状态记录
- 包含统计信息查询便于验证结果

## 预期效果
- 性能提升10倍以上
- 用户体验改善
- 代码更简洁易维护
