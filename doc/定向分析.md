[#本地化定向分析]

任务：修复通知中心删除通知 401 问题

问题现象：
- 前端报错：NotificationContext.tsx:189 Failed to delete notification: Error: HTTP 401: Unauthorized

关键调用链：
- UI 删除动作 -> `NotificationContext.deleteNotification(id)` -> `api.notifications.delete('/api/v1/notifications/:id')` -> Next 重写到 Go 后端 -> Go 路由 `DELETE /api/v1/notifications/:id`（需 JWT）

根因定位：
- 弹窗登录组件 `src/components/AuthModal.tsx` 使用 `fetch('/api/auth/login')` 走本地 Next 路由登录，仅在超级管理员时写入 `auth_token` Cookie，不返回访问 Go 后端所需的 `access_token`，导致 `localStorage.authToken` 为空。
- `src/lib/api-client.ts` 仅从 `localStorage.authToken` 注入 `Authorization: Bearer <token>`。因此通过弹窗登录的普通用户发起删除通知请求时缺少 Authorization 头，后端 `middleware.Auth()` 返回 401。

修复方案：
- 将 `AuthModal` 登录/注册切换为调用统一 API 客户端 `api.auth.login/register`，该路径映射至 Go 后端并返回 `access_token/refresh_token`，`api-client` 会自动持久化 token；并通过 `onSuccess(user, token)` 传递给 `AuthContext.login(user, token)` 再次确保本地保存。
- `Navbar` 中对 `AuthModal` 的 `onSuccess` 增加 `token` 透传到 `login`。

受影响文件：
- `src/components/AuthModal.tsx`
- `src/components/Navbar.tsx`

结果：
- 登录后 `localStorage.authToken` 存在，通知删除请求携带 `Authorization` 头，通过后端认证，中止 401。

注意：
- 项目内仍存在硬编码中文字符串（历史代码），本次未做大规模 i18n 重构以避免扩大改动面。
